# RopeBridge Bootstrap Context

## Project Overview
RopeBridge is a persistent physical-to-digital interaction system built around QR-driven flows.

Current active archetype:
- SamplePass

Core philosophy:
- frictionless participation
- artisan/local aesthetic
- persistent recognition continuity
- editable live destinations
- sign in once, easier forever
- bones + config architecture

The product is NOT a QR generator.
The product is persistent interaction infrastructure.

# Live Routes

## Vendor Creator
/create/

Purpose:
- inline mobile-first editor
- create vendor pages
- edit existing pages
- upload images
- manage socials
- launch live pages

Behavior:
- if slug already exists, update existing page
- no duplicate vendor pages
- intended to feel editorial/tactile, NOT dashboard-like

## Dynamic Vendor Pages
/sample/?slug=vendor-name

Purpose:
- live customer-facing page
- persistent destination
- recognition continuity
- interaction tracking

# Current System State

The following systems are LIVE and functioning:

## Persistent Vendor Pages
Flow:
create -> persist -> revisit -> edit -> relaunch

Vendor pages are stored in Supabase.

## Recognition Continuity
Visitors receive a persistent browser identity token.

Returning visitors are recognized automatically.

Current UX copy:
"Welcome back — your details are already recognized."

## Interaction Tracking
Interactions are stored.

Foundation exists for:
- repeat visitors
- vendor relationship history
- future loyalty/rewards
- cross-vendor continuity

## Real Image Hosting
Vendor images are uploaded to Supabase Storage.

Images are NOT stored as giant base64 blobs in database rows anymore.

# Current Known Technical Debt

## Recognition
Current recognition is browser/device-based only.
Future versions may incorporate:
- phone number continuity
- SMS OTP
- cross-device recognition

## Security
Current RLS policies are intentionally permissive for MVP velocity.
Needs tightening later.

## Slugs
Current slug system is simplistic.
No collision handling beyond updating existing pages.

## Image Optimization
No resizing/compression pipeline yet.
